# 라스트 서바이벌 — Roblox Studio 제작 작업 순서와 Claude 프롬프트

`docs/GDD.md` v1.0을 Roblox Studio(한국어, 최신 버전)로 만드는 순서다. 작업을 Studio에서 할 일 단위로 나누고, 단계마다 Claude Code에 붙여넣을 프롬프트를 붙였다.

> Studio 메뉴 이름은 `한국어 (English)`로 적었다. Studio 버전에 따라 이름이나 위치가 조금 다를 수 있다.

---

## 1. 작업 방식

```
┌──────────────────────── 내 PC ────────────────────────┐
│                                                        │
│  Claude Code (이 저장소 폴더에서 실행)                  │
│     │                                                  │
│     ├─ ① 코드 작성: src/*.luau ──▶ Rojo ──▶ Studio      │
│     │                                                  │
│     └─ ② Studio MCP ──▶ Studio 직접 조작               │
│          (맵 블록 배치, 태그, 플레이테스트, 출력 읽기)   │
│                                                        │
│  Roblox Studio (한국어) ── 저장/게시 ──▶ Roblox 클라우드 │
└────────────────────────────────────────────────────────┘
```

| 무엇을 | 어디에 저장 | 누가 만드나 |
|---|---|---|
| 스크립트 (게임 로직, UI 코드) | Git 저장소 `src/` | Claude Code가 파일로 작성 → Rojo가 Studio에 반영 |
| 맵, 파트, 조명, 태그 | Studio 플레이스 (Roblox 클라우드) | Claude가 Studio MCP로 배치, 사람이 다듬음 |
| 게임 설정, 게임패스, 배지, 성숙도 설문 | Roblox (Studio·Creator Hub) | **사람이 직접** |

**Claude가 대신할 수 없는 일** (각 단계의 🧑 항목): Roblox 로그인, 게임 게시, 보안·권한 설정 켜기, Creator Hub의 상품·배지·설문, 여러 명이 접속하는 테스트 실행과 재미 판단.

### 각 단계를 진행하는 방법
1. 🧑 **Studio에서 할 일**을 먼저 한다.
2. 🤖 **프롬프트**를 복사해서 Claude Code에 붙여넣는다.
3. ✅ **완료 확인**을 직접 해본다. 문제가 있으면 Claude에게 증상을 그대로 말한다.
4. Studio에서 저장(Ctrl+S)한다. Claude는 단계마다 Git 커밋을 한다.

프롬프트는 짧게 유지하기 위해 저장소의 `CLAUDE.md`(공통 규칙, 맵 태그, 단계 완료 절차)를 기준으로 쓴다. Claude Code는 이 파일을 자동으로 읽는다.

## 3. S0 — 준비

### S0-1. 프로그램 설치

🧑 **할 일**
1. Roblox Studio 최신 버전을 설치하고 로그인한다.
2. Studio 언어를 한국어로 설정한다 (Roblox 계정 언어 설정 또는 Studio 설정의 언어 항목).
3. Git, Claude Code를 설치한다.
4. [Rokit](https://github.com/rojo-rbx/rokit)을 설치한다 (Rojo·Wally·Selene·StyLua 버전을 관리하는 도구).
5. GitHub 저장소 `smileted111/claude-roblox-p1`을 PC에 받는다 (`git clone`).
   > 지금은 Claude 클라우드 세션에서 GitHub로 올리는 데 실패한 상태다. 먼저 https://claude.ai/connect-github 에서 GitHub를 연결해 기획서 커밋을 올려야 PC에서 받을 수 있다.
6. 저장소 폴더에서 Claude Code를 실행한다.

🤖 **프롬프트**
```text
이 PC에서 라스트 서바이벌 개발을 시작하려고 해. 다음을 확인해서 표로 알려줘.
- git, rokit 설치 여부와 버전
- 이 폴더가 smileted111/claude-roblox-p1 저장소이고 docs/GDD.md, CLAUDE.md가 있는지
- 없는 프로그램이 있으면 이 운영체제에서 설치하는 방법
아직 아무것도 설치하거나 수정하지는 마.
```

✅ **완료 확인**: Claude가 알려준 표에서 모든 항목이 "있음"이다.

### S0-2. 새 게임 만들고 게시

🧑 **할 일**
1. Studio 시작 화면에서 **새로 만들기 (New) → 기본 플레이트 (Baseplate)** 를 연다.
2. **파일 (File) → Roblox에 게시 (Publish to Roblox)** 를 누르고 새 게임으로 게시한다.
   - 이름: `라스트 서바이벌`, 소유: 개인 계정 또는 그룹 (질문지 Q8-5)
   - 게임은 처음에 **비공개**로 둔다.
3. **홈 (Home) → 게임 설정 (Game Settings)** 에서 아래를 설정하고 저장한다.
   - **보안 (Security)**: `Studio의 API 서비스 액세스 허용 (Enable Studio Access to API Services)` 켜기 → Studio에서 데이터 저장 테스트에 필요
   - **아바타 (Avatar)**: 아바타 유형 `R15`
   - **기본 정보 (Basic Info)**: 최대 플레이어 수 `8`
4. [Creator Hub](https://create.roblox.com/dashboard/creations)에서 이 게임의 **Universe ID**와 **Place ID**를 찾아 메모한다.

🤖 **프롬프트**: 없음 (사람만 할 수 있는 작업)

✅ **완료 확인**: Creator Hub에 "라스트 서바이벌"이 비공개로 보이고, ID 두 개를 메모했다.

### S0-3. Studio MCP 연결

🧑 **할 일**
1. Studio에서 **어시스턴트 (Assistant)** 창을 열고 **설정 → MCP 서버 (MCP Servers)** 로 간다. 버전에 따라 `MCP 서버 관리 (Manage MCP Servers)`로 보일 수 있다.
2. `Studio를 MCP 서버로 사용 (Enable Studio as MCP server)`을 켠다.
3. **빠른 연결 (Quick connect)** 에서 **Claude Code**를 켠다.
4. Claude Code를 다시 시작하고 `/mcp`를 입력해 Studio 서버가 연결되었는지 본다.

🤖 **프롬프트**
```text
Roblox Studio MCP가 연결되었는지 확인해줘.
1. 사용할 수 있는 Studio MCP 도구 목록을 짧게 알려줘.
2. 현재 열린 플레이스의 Workspace 자식 목록을 읽어서 보여줘.
3. Luau로 print("MCP 연결 확인")을 실행하고 출력 창에 찍혔는지 확인해줘.
플레이스를 수정하지는 마.
```

✅ **완료 확인**: Studio 출력 창에 `MCP 연결 확인`이 보인다.

### S0-5. Rojo 연결

🤖 **프롬프트**
```text
Rojo를 연결했어. Studio MCP로 확인해줘.

3. 플레이테스트를 멈추고 결과를 알려줘. 문제가 있으면 고치고 다시 확인해줘.
```

✅ **완료 확인**: 플레이 중 출력 창에 `started` 로그가 모두 찍히고 빨간 오류가 없다. Studio에서 저장(Ctrl+S).

### S1-3. 매치 루프·역할 배정

🧑 **할 일**: 테스트할 때 **테스트 (Test)** 탭 → **클라이언트 및 서버 (Clients and Servers)** 에서 플레이어 수를 1명, 3명으로 바꿔가며 실행한다.

🤖 **프롬프트**
```text
GDD 2.1, 3장, 5장을 기준으로 MatchService, StageService, RoleService를 구현해줘. 지금은 스테이지 1만 반복해도 돼.
- 흐름: 대기(최소 1명, 10초) → 역할 공개 5초 → 준비 15초 → 추격(제한 시간) → 결과 10초 → 다시 대기.
- 맵: ServerStorage.Maps.Stage1을 복제해 Workspace.CurrentMap에 놓고, 스테이지가 끝나면 제거.
- 역할: 플레이어 2명 이상이면 1명을 추격자로(덜 해본 사람 우선, 같으면 무작위). 1명이면 추격자 없음(솔로).
- 생존자는 SurvivorSpawn, 추격자는 ChaserSpawn에 배치. 준비 시간 동안 ChaserGate를 닫아 두고 끝나면 연다.
- 플레이어 Attribute로 Role, SurvivorState를 공개하고, 남은 시간·단계는 ReplicatedStorage의 Attribute나 리모트로 클라이언트에 알려줘.
- 종료 조건: 시간 종료, 생존자 전원 잡힘, 추격자 이탈 시 괴물만으로 계속(GDD 5장 표).
- 아직 잡기·괴물·UI는 없음. 단계 전환을 출력 창 로그로 남겨줘.
단계 완료 절차를 따라줘. 플레이테스트는 1인 기준으로 하고, 3명 테스트는 나에게 요청해줘.
```

✅ **완료 확인**
- 1명: 추격자 없이 진행되고, 출력 창에 단계 전환 로그가 보인다.
- 3명: 1명은 대기실에서 시작하고 15초 뒤 문이 열린다.

### S1-4. 생존자 이동·달리기·숨기

## 7. 막혔을 때 쓰는 프롬프트

| 상황 | 프롬프트 |
|---|---|
| 출력 창에 오류 | `Studio 출력 창의 최근 오류를 읽고 원인과 수정 방법을 알려준 뒤 고쳐줘. 고친 뒤 플레이테스트로 다시 확인해줘.` |
| 기능이 기획과 다르게 동작 | `<기능>이 <실제 동작>처럼 동작하는데 GDD <장>에서는 <기대 동작>이야. 원인을 찾아 고치고 확인해줘.` |
| Rojo 동기화가 이상함 | `Rojo 동기화 상태를 점검해줘. default.project.json 매핑과 Studio 탐색기 구조를 비교하고, Studio에서 만든 맵이 지워질 위험이 없는지도 확인해줘.` |
| 기획을 바꾸고 싶음 | `기획을 바꾸려고 해: <변경 내용>. GDD와 이미 구현된 코드에 미치는 영향을 먼저 정리해주고, 승인하면 GDD → 코드 순서로 반영해줘.` |
| 다음에 뭘 할지 모름 | `docs/progress.md를 보고 다음 단계와 그 단계의 프롬프트를 알려줘.` |
